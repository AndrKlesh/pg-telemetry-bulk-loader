# Разработка высокопроизводительного загрузчика данных телемеханики  
## Цель работы
Исследовать возможность достижения скорости вставки 100 000 записей/сек в PostgreSQL 12+ с использованием команды COPY при загрузке данных временных рядов из CSV-файлов.  

## Контекст  
Система телемеханики генерирует большие объемы измерений, которые необходимо оперативно загружать в базу данных для последующего анализа и мониторинга в реальном времени.

## Технические требования

### Стек технологий
Языки программирования на выбор:
- C/C++
- Rust
- C#

### Формат приложения:
**Программа должна:** 
- Представлять собой консольное приложение (CLI).
- Взаимодействовать с PostgreSQL 12+ через официальные библиотеки.
> **Примечание:** Для исследований лучше взять актуальную версию PostgreSQL.
- Вести лог своих действий в консоль  с корректным уровнем логгирования (Critical, Error, Warning, Debug, Trace).
- Поддерживать метрики:
  + Время загрузки всего набора данных.
  + Время загрузки порции данных из буфера набора данных.
  + Средняя скорость (записей/сек).
  + Максимальная скорость (пиковая).
  + Использование памяти (RSS) в процессе загрузки.
  + Количество созданных секций.
  + Время, затраченное на создание секций.

### Структура базы данных

База данных должна содержать одну таблицу измерений.
Для этой таблицы необходимо использовать декларативное секционирование по интервалу один месяц.  

Структура таблицы:
```
CREATE TABLE measurements (
    measure_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    object_id INT NOT NULL,
    measure_type_id INT NOT NULL,
    value DOUBLE PRECISION NOT NULL,
    timestamp TIMESTAMP NOT NULL,
    insert_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) PARTITION BY RANGE (timestamp);
```

Пример создания секции:

```
CREATE TABLE measurements_2026_07 PARTITION OF measurements
    FOR VALUES FROM ('2026-07-01') TO ('2026-08-01');
```

### Формат входных данных

Приложение должно принимать CSV-файлы со следующей структурой:
```
object_id,measure_type_id,value,timestamp
1001,1,23.5,"2026-07-15 14:30:00"
1002,2,45.2,"2026-07-15 14:30:01"
```
Приложение должно проводить валидацию строк по правилам:
- Все поля, кроме insert_time, обязательны. Поле insert_time заполняется при вставке в БД.
- object_id > 0.
- measure_type_id > 0.
- value — число с плавающей точкой.
- timestamp — корректная дата/время в формате ISO (YYYY-MM-DD HH:MM:SS).
- При несоответствии строка считается невалидной, запись отбрасывается с выводом ошибки в лог.

### Алгоритм работы приложения
1. **Сканирование каталога:** Принимает путь к каталогу как аргумент командной строки. Обрабатывает все файлы с расширением .csv.  

2. **Чтение данных в буфер:** Использовать фиксированный буфер (например, 10000 строк) для чтения файла. Размер буфера должен настраиваться через аргументы командной строки. 
> **!Важно:** Запрещено загружать весь файл в память.

3. **Парсинг и валидация:** Разбор строки, проверка по правилам, описанным выше.

4. **Предварительная сортировка:**: Необходимо отсортировать данные в буфере по возрастанию ключа секционирования (timestamp).
> **Обоснование:** Это критично для производительности COPY, так как позволяет использовать оптимизацию multi-insert для секционированных таблиц и минимизировать переключения между секциями.

5. **Создание секций:** Перед выполнением COPY для группы записей необходимо убедиться, что секция на соответствующий месяц существует. Если секция отсутствует, создать её автоматически с помощью команды CREATE TABLE ... PARTITION OF.

> **!Важно:** Секции должны создаваться до начала вставки данных в них.

6. **Пакетная загрузка через COPY:** Отправить данные из буфера в PostgreSQL через COPY ... FROM STDIN.

7. **После завершения вставки порции данных**
   - Вывести в лог текущие значения метрик
   - Перейти к следующей порции данных загружаемых в буфер.

**Завершение работы программы:** Выполнить расчет средней скорости вставки и вывести в лог вместе с значениями остальных метрик.

## Экспериментальная часть

### Гипотеза
Использование COPY с предварительной группировкой и сортировкой данных по секциям, а также автоматическим созданием секций, позволяет достичь скорости вставки ≥ 100 000 записей/сек на тестовом стенде.
### План эксперимента
#### Генерация тестовых данных:
Написать скрипт (Python/Shell) для генерации CSV-файлов.
Общий объем: минимум 1 млн записей.
Данные должны покрывать 2-3 месяца для проверки работы секционирования.

##### Эксперимент №1.
Сгенерировать один файл на 1 млн записей, отсортированных по timestamp.

##### Эксперимент №2.
Сгенерировать несколько файлов (20-50) на 1 млн записей, в каждом из которых данные отсортированы по timestamp.

##### Эксперимент №3.
Сгенерировать один файл на 1 млн записей, в котором данные не сортированы.

##### Эксперимент №4.
Сгенерировать несколько файлов (20-50) на 1 млн записей, в каждом из которых данные не сортированы.

В каждом эксперименте провести замеры производительности:
- Время загрузки всего набора данных.
- Время загрузки порции данных из буфера набора данных.
- Средняя скорость (записей/сек).
- Максимальная скорость (пиковая).
- Использование памяти (RSS) в процессе загрузки.
- Количество созданных секций.
- Время, затраченное на создание секций.

**После выполнения всех экспериментов** Сравнить время выполнения и скорость вставки.
